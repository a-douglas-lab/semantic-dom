# Semantic DOM Constitution

## Core Principles

### I. Beat the Strongest Baseline
Every efficiency claim is measured against **B1** (full document in context, prompt caching,
find-and-replace edits), including its 1-hour-TTL variant, never only against the naive full-rewrite
strawman (B0). Headline numbers MUST quote "S vs best B1". Rationale: savings against a strawman
are not savings anyone can realise.

### II. Honest, Pre-Registered Reporting
Success rubrics and the kill criterion are fixed in this constitution *before* results are seen.
Results MUST report where S loses (small docs, warm caches, paraphrase ripples, global renames).
Estimates (chars/4 tokens, latency constants, oracle outputs) MUST be labelled as estimates.
Changing a rubric after seeing results requires a constitution amendment with stated reason.

### III. Reproducibility
Corpus generation is seeded and deterministic. Every results file records model ID, effort,
date, git commit, and corpus manifest. Any reported number can be regenerated by one command.

### IV. Gated Changes (NON-NEGOTIABLE)
No change is complete until `python -m tools.gate` passes: ruff (lint + format), mypy, pytest
(unit + eval regression). Bug fixes start with a failing test. Unit tests make no network calls.

### V. Simplicity
Core library (`sdom/`) depends on the standard library only; the Anthropic SDK is confined to
runners. New dependencies need a one-line justification in the plan. Prefer deterministic local
operations over LLM calls wherever they are exact (e.g. literal renames).

### VI. Bounded Autonomy and Spend
The agent works without waiting for approval inside the Autonomy Contract below. Every live API
call is recorded in the spend ledger and is refused by the runner if it would exceed the budget.

## Success Rubrics

### R1 — Efficiency (hypothesis H1; kill criterion)
On docs ≥15k tokens, in the `human` scenario (pauses 2–12 min):
| Grade | S cost vs best B1 |
|---|---|
| Fail (kill efficiency claim) | < 30% saving |
| Pass | ≥ 30% saving |
| Strong | ≥ 50% saving |
Measured offline first, then confirmed live (live result wins when they disagree).

### R2 — Edit quality (hypothesis H2; must hold for any R1 pass to count)
Live, per strategy, averaged over cases:
- must-change recall: S ≥ B1 − 5 pp
- fact checks passed: S ≥ B1 − 5 pp
- collateral changes: S ≤ B1
- distractor changes: S ≤ B1
- apply/parse errors: ≤ 2% of ops

### R3 — Latency
S mean end-to-end latency ≤ B1 on docs ≥15k tokens (live measurement).

### R4 — Impact analysis (offline regression floor)
Context recall ≥ 95% on every edit kind except `paraphrase-ripple` (a known v1 gap, tracked separately).
The gate fails if recall regresses below the floor recorded in `tests/eval_floor.json`.

### R5 — Code quality
ruff clean; mypy clean on `sdom/`; pytest green; line coverage on `sdom/` ≥ 80%.

### R6 — Publishable result
Before any public write-up: ≥ 3 live runs per case with spread reported, at least one real
(non-synthetic) document per doc type, explicit limitations section, reproduction instructions.

## Engineering Loop & Autonomy Contract

**Loop** (one iteration per backlog item):
1. Pick the top unblocked item in `backlog.md`; for non-trivial items run the Spec Kit flow
   (`specify` → `plan` → `tasks`) under `specs/NNN-name/`.
2. Write or adjust tests first; implement; run `python -m tools.gate` until green.
3. Run the offline eval; run live eval only if the item needs it and budget allows.
4. Score against R1–R6; record findings in the spec folder and results.
5. Update `backlog.md`; commit locally with a message referencing the spec/backlog item.
6. Continue to the next item; stop and report at a decision point listed below.

**Allowed without approval**: edits to code, tests, specs, backlog and results; offline runs; local
git commits on feature branches; live API runs within budget; adding dev-only tooling (ruff,
mypy, pytest, coverage).

**Requires owner approval**: exceeding the spend budget; amending this constitution (including
rubrics and kill criterion); pushing to any remote or publishing anything (LinkedIn, gists,
artifacts shared beyond the owner); adding runtime dependencies to `sdom/`; deleting results.

**Spend budget**: per-run cap and cumulative cap are read from `budget.json` (owner-set). The
live runner refuses to start a call that would exceed either. TODO(owner): confirm values.

## Governance

This constitution supersedes other practices in this repo. Amendments: propose the change with a
reason, get owner approval, bump the version (MAJOR: principle/rubric redefinition or removal;
MINOR: new principle/section; PATCH: wording), update the date. Every plan's Constitution Check
verifies Principles I–VI and the relevant rubrics.
